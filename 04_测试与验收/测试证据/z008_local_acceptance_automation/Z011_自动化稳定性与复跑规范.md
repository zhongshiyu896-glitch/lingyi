# Z011 自动化稳定性与复跑规范

- `task_id=TASK-Z011B-03-IMPL`
- `source_head=44bed39c58dc68493a36cbb49391e458ea24a231`
- `scope=Z008/Z009 local acceptance automation`

## 1. 目标

- 统一本地验收自动化在复跑时的稳定性行为与输出约束。
- 避免污染既有已提交证据，保证复跑可审计与可复现。
- 保持当前 skip-aware 残余语义，不把边界跳过误判为闭合。

## 2. 默认 timeout 建议

- 纯文件解析脚本：`120s`
- Git gate 脚本：`90s`
- pytest/contract matrix 脚本：`900s`
- browser GET-only smoke 脚本：`900s`
- orchestrator 脚本：`1200s`
- post-orchestrator regression gate 脚本：`300s`

## 3. 输出目录隔离

- 复跑输出默认写入 `/tmp/<task_or_run_id>/` 或显式 run-id 目录。
- 不覆盖 `z008_local_acceptance_automation/` 下已提交证据文件。
- 截图、缓存、`__pycache__`、`.pyc`、`test-results`、`.ci-reports`、`node_modules`、`dist`、`.vite` 不纳入 ledger。

## 4. 复跑命令一致性

- Python 脚本统一使用 `python3`。
- Node 脚本先执行 `node --check` 再运行。
- 每次复跑应同时产出 result JSON 与 result TSV，并保证条目顺序一致。
- orchestrator / regression gate 复跑建议命令模板应显式声明 `--output-json` 与 `--output-tsv`。

## 5. 失败分类规则

- `PASS`：检查通过且符合边界。
- `BLOCKING`：关键门禁失败或出现越界动作。
- `RESIDUAL`：不阻断主链但仍需保留风险说明。
- `SKIPPED_BY_BOUNDARY`：因前置条件未满足而跳过，禁止伪造 PASS。

## 6. 安全边界

- `write_request_count=0`
- `production_account_used=false`
- `remote_lifecycle_action_executed=false`
- 不读取 `cookie/localStorage/sessionStorage/token`
- 不执行 push/PR/tag/release

## 7. 当前残余保留

- `full_browser_route_smoke_closed=false` 必须保留。
- `Z008-SCRIPT-005` 在登录态缺失时应保持 `SKIPPED_BY_BOUNDARY`。
- 只有在用户完成人工登录态并满足 `Z009_BROWSER_LOGIN_READY=1` 的前置条件后，才可在只读边界复跑 browser smoke 尝试闭合。
